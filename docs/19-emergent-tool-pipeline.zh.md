# 涌现工具晋升管线

生成的工具在完成每一阶段的人工晋升前均视为不可信数据：

```text
proposed --（沙箱/评判门禁 + 人工批准）--> session_enabled
session_enabled --（租户门禁 + 人工批准）--> tenant_candidate
tenant_candidate --（发布门禁 + 人工批准）--> published
```

人工审查者可以将任何非终态记录转为 `rejected`；`rejected` 和 `published` 都是终态。系统特意不提供从提案直接晋升为 `published` 的 API。

## 安全与隔离

- 内核不执行生成的代码。`EmergentToolGate` 适配器负责评估，通常委派给外部隔离沙箱和评判服务。
- 门禁失败或服务不可用时，记录保持在当前状态。
- 每次晋升都会保存门禁结论、评估者、具名批准人和时间戳。
- 从 `session_enabled` 到 `tenant_candidate` 的晋升还必须提供已完成且具名的规则审查清单，覆盖安全、租户隔离和声明的副作用；审计记录会将该审查和门禁结论绑定到已审定义的 SHA-256 摘要。
- `EmergentToolStore` 需要已验证的租户标识，并应使用通过验证租户声明打开的 L0 存储。读取和修改还会再次校验记录所属租户，其他租户无法枚举或晋升该记录。
- 创建提案只保存草稿记录，不写入技能图、注册表或生产工具入口。发布集成只能使用状态为 `published` 的记录。

## 集成约定

请为部署中可用的沙箱/测试/评判服务实现 `EmergentToolGate`。每次请求状态迁移前都会调用其 `evaluate` 方法；只有相应的沙箱、测试、策略与评判检查完成后，才能返回通过结论。

## Graph Engineering 跨切

租户级晋升是监督环，而不是优化器的结果：冻结的 golden 输入/输出夹具由包中声明的 SHA-256 摘要固定，并在评测前验证；夹具一旦变更即被拒绝，不会重新计分。独立的规则审查环及其具名人工审查者在工具获得租户可见性前检查安全、隔离与副作用。晋升审计字段保留候选定义摘要、门禁证据、审查者和时间。

这就是“loops watching loops”：生成器可以优化候选项，但不能改写自己的评分卡，也不能自行取得租户级权限。
